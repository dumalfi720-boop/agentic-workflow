MODULE 2.6

🛡️ Security and guardrails

This module teaches you how to limit the right system: scope of tools, sensitive actions, prompt injection, unreliable data and human approval.

6
Topics
45
Minutes
core
Level
SEC
Type
1

🔒 Scope of tools

Every exposed tool increases the risk surface. The agent should not have greater access than necessary.

Main concept

Minimum permission reduces impact of failure, abuse or improper call.

Practical tip

Separate reading, writing and administration tools. Don't mix everything into a generic endpoint.

2

💥 Destructive actions

Deleting, moving, publishing, paying for and changing critical data require additional barriers.

Good control

Dry-run, explicit confirmation and audit trail before the final side effect.

High risk

Allow irreversible execution without human review or rollback possible.

3

🧨 Prompt injection

External content may attempt to reprogram the agent. The system needs to treat inputs as potentially hostile.

Technical criteria

Separate system instructions from external data and limit what can trigger tools.

Common fault

Trusting scraped text, email or document as if it were part of the secure prompt.

4

📥 Unreliable data

External API, user file, scraped HTML, and uploaded spreadsheet can break flow assumptions.

Main concept

Validation, sanitization and schema limits are part of security, not implementation details.

Alert

If dirty input reaches the decision-making stage, the risk is already within the system.

5

👤 Human controls

Human in the loop is not an ornament; It is a risk, governance and operational quality decision.

Use when

There is high ambiguity, financial impact, external publication or irreversible action.

Don't confuse

Human approval does not fix bad architecture; it complements technical controls.

6

🧪 Security laboratory

Closing the module with a risk checklist, approval policy and clear execution limits for a practical case.

Exercise

Map tools, classify risk, identify hostile inputs and define human gates.

Deliverable

Risk checklist with approval policy and list of implementable guardrails.

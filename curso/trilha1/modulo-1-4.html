MODULE 1.4

🧰 Tool design and schemas

This module transforms the student into someone capable of designing small, understandable tools that are more resistant to incorrect agent calls.

6
Topics
45
Minutes
Base
Level
Design
Type
1

📝 Tool description

Before thinking about code, the engineer needs to write the tool's role well. Good description reduces misuse and helps the agent make better choices.

Main concept

A tool needs to explain what it is for, when it should be called and when it should not be called.

Alert

A pretty name without a clear scope becomes an invitation for misuse.

2

📦 Entry and exit scheme

Schema is not bureaucracy. It is the mechanism that reduces ambiguity, simplifies validation and improves interoperability.

Good schema

Clear fields, defined types, enums when necessary and predictable output shape.

Bad schema

Vague parameters, too many optional fields and inconsistent return.

3

✅ Validation and types

Validation is the minimum barrier between a poorly formed request and a real-world side effect.

Technical criteria

If the parameter does not pass validation, the tool does not execute. This reduces risk and facilitates debugging.

Practical tip

Always differentiate between format errors, missing data and insufficient authorization.

4

🚨 Recoverable and non-recoverable errors

Not every failure deserves a retry. Part of engineering talent is classifying errors and responding with the right strategy.

Recoverable

Timeout, temporary unavailability or dependence momentarily out.

Not recoverable

Invalid input, permission denied and action prohibited by policy.

5

👤 Human approval and side effects

The greater the impact of the action, the less free autonomy should be. The module reinforces this rule before the advanced track.

Main concept

Deleting, sending, changing or spending resources requires human preview and gate when there is a relevant risk.

Alert

“The agent knows what he is doing” is not security policy.

6

🧪 Tool calling laboratory

The student designs 3 tools, tests valid and invalid calls and refines the description based on the errors observed.

Exercise

Create a reading tool, a transformation tool and an action tool with a schema and standardized error message.

Deliverable

Package with 3 tool definitions, payload examples and validation table.

✅ Final summary

✓ Learned how to write good tool descriptions.

✓ Understood the role of schemas and validation.

✓ Saw how to classify failures and protect side effects.

✓ Understood why human approval is part of design.

✓ Left with a small kit of correctly designed tools.
